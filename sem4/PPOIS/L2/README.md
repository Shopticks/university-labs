## VetJournal — журнал ветеринарной клиники

Десктопное приложение для ведения карточек посещений: имя питомца, даты рождения и последнего визита, ФИО ветеринара, диагноз. Поддерживает добавление, поиск, удаление по критериям, постраничный просмотр в виде таблицы или дерева, а также обмен данными через XML.

#### 1. Стек технологий

*   **Язык программирования:** Python 3.11+
*   **Библиотека GUI:** PySide6 (Qt 6).
*   **Работа с данными:** SQLAlchemy ORM (база данных PostgreSQL, драйвер `psycopg2`). Схема создаётся автоматически при первом подключении (`Base.metadata.create_all`).
*   **Работа с XML:**
    *   `xml.dom.minidom` (DOM) — для генерации XML при экспорте.
    *   `xml.sax` (SAX) — для эффективного потокового чтения данных при импорте.
*   **Сборка интерфейса:** UI описан в `.ui`-файлах (Qt Designer), Python-обёртки генерируются `pyside6-uic` / `pyside6-rcc`. Стили заданы инлайновым QSS внутри `.ui`.

#### 2. Архитектура приложения (MVC)

Приложение реализовано с чётким разделением ответственности:

*   **Model (Модель):** Класс `DBManager` (`src/model/db_manager.py`) — единственный источник правды. Отвечает за всё взаимодействие с PostgreSQL через SQLAlchemy: пагинированное чтение (`get_page`), полная выборка (`get_all`), добавление (`add`), фильтрация (`search`), подсчёт совпадений (`count_matching`), удаление по критериям (`delete_matching`) и пакетная замена (`replace_all` — для XML-импорта). Наследуется от `QObject` и эмитит сигнал `data_changed` после любой мутации, чтобы View обновлялся автоматически. Класс `XmlHandler` (`src/model/xml_handler.py`) инкапсулирует DOM-экспорт и SAX-импорт.
*   **View (Представление):** Набор классов в папке `src/view`. Включает главное окно (`MainWindow`), универсальный диалог `RecordDialog` (один на три режима: ADD / SEARCH / DELETE) и адаптер `PetTableModel` для `QTableView`. View ничего не знает про источник данных — общается с контроллером только через Qt-сигналы (`add_requested`, `search_requested`, `delete_requested`, `save_requested`, `load_requested`, `close_connection`, навигация по страницам). Также экспонирует тонкий UI-API (`confirm`, `notify`, `ask_save_path`, `ask_open_path`, `create_record_dialog`), чтобы контроллер не работал с `QMessageBox` / `QFileDialog` напрямую.
*   **Controller (Контроллер):** Класс `MainController` (`src/controller/main_controller.py`). Подписывается на сигналы View, вызывает методы модели, оркестрирует флоу диалогов (поиск/удаление в цикле, подтверждения, выбор XML-файла) и управляет состоянием пагинации. Не импортирует Qt-виджеты — все UI-операции делегируются методам `MainWindow`. При закрытии окна освобождает пул соединений PostgreSQL через `DBManager.close()`.

#### 3. Ключевые особенности реализации

1.  **Эффективная пагинация:** Реализована поддержка постраничного вывода (`LIMIT` / `OFFSET` на уровне БД) с сортировкой по дате последнего визита.
2.  **Гибкий поиск и удаление:** Поиск по составным критериям (имя питомца, ФИО ветеринара, фраза из диагноза; даты — точным совпадением). Универсальный диалог `RecordDialog` переключается между режимами без дублирования кода.
3.  **Реактивное обновление View:** Модель эмитит сигнал `data_changed` после каждой мутации; контроллер автоматически перерисовывает таблицу — никаких ручных вызовов `_refresh()` после CRUD.
4.  **Два представления данных:** Одни и те же записи отображаются как `QTableView` с моделью `PetTableModel` или как `QTreeWidget` (древовидный вид). Переключение по кнопке без потери позиции.
5.  **Пакетная обработка XML:** Импорт реализован через SAX-парсер, что гарантирует низкое потребление оперативной памяти при загрузке больших файлов. Экспорт через DOM форматированием.
6.  **Валидация данных:** Обязательные поля (имя питомца, ФИО, диагноз) проверяются на стороне dataclass `PetRecord` через `validation_errors()`; диалог не закрывается, пока ошибки не исправлены.
7.  **Скрипт сборки и запуска:** `launch.sh` ре-генерирует `.py`-обёртки из `.ui`-файлов (`pyside6-uic`/`pyside6-rcc`), патчит импорты ресурсов и запускает приложение в проверенном conda-окружении. Флаг `--no-build` пропускает пересборку и запускает уже собранное приложение.

#### 4. Обработка исключений и UX

*   Перед деструктивными операциями (удаление записей, импорт с затиранием базы) реализованы подтверждающие диалоги `QMessageBox.question` с предварительным показом числа затронутых строк.
*   Все критические операции (файловый ввод-вывод XML) обёрнуты в `try…except` с выводом дружелюбных уведомлений (`QMessageBox.warning`); при сбое импорта база остаётся нетронутой — `replace_all` вызывается только если SAX-парсинг прошёл успешно.
*   Поиск и удаление работают в цикле: после нажатия «Найти» / «Удалить» диалог переоткрывается с результатами, пользователь может уточнить критерии без повторного открытия окна.
*   При попытке удалить по критериям, под которые не подходит ни одна запись, показывается информационное сообщение, а БД не трогается.
*   Интерфейс поддерживает динамическую смену количества записей на странице.

#### 5. Запуск

1.  Активировать conda-окружение с зависимостями (по умолчанию `base`).
2.  Создать БД (один раз):
    ```bash
    createdb vetjournal
    ```
3.  Запустить через скрипт сборки:
    ```bash
    ./launch.sh                  # пересобрать UI/ресурсы и запустить
    ./launch.sh --no-build       # запустить без пересборки
    ./launch.sh --conda_env myenv  # с другим conda-окружением
    ```
    Скрипт ре-генерирует UI/resources (если не указан `--no-build`) и запускает `python -m src`.
