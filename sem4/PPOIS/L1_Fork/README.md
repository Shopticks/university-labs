# Лабораторная работа №1

**Предметная область:** моделирование работы системы городского метрополитена.

**Важные сущности:** пассажир, поезд, станция метро, платформа, турникет, билет, расписание.

**Операции:** операция продажи билетов, операция посадки и высадки пассажиров, операция обслуживания поездов, операция безопасности, операция поддержания расписания.

---

**Дополнительные важные сущности:** деньги, кассовый аппарат, маршрут.

**Дополнительные операции:** операция включения и выключения локдаунда (полная блокировка турникетов), операция управления временем, операция прохода через турникет, операция посадки/высадки пассажиров, операция управления движением поездов, операция сохранения и загрузки состояния системы.

---

## О программе

Программа представляет собой имитационную модель системы метрополитена с полным жизненным циклом пассажира: от покупки билета до выхода на конечной станции.

Система позволяет:

- Создавать станции, добавлять к ним платформы, турникеты и кассовые аппараты
- Создавать поезда и маршруты между станциями
- Управлять пассажирами: покупка билетов, вход через турникет, ожидание на платформе, посадка в поезд
- Симулировать движение поездов по маршруту в реальном времени, используя такты
- Вводить режим локдауна на станциях (блокировка всех турникетов)
- Просматривать статус всей системы: пассажиры, поезда, станции, активные рейсы
- Сохранять и загружать состояние системы в JSON-файл

Управление осуществляется через интерфейс командной строки. Вся логика разделена по слоям архитектуры: домен, приложение, инфраструктура, представление.

## 📊 Диаграмма классов

Диаграмма классов отражает архитектурное разделение системы на слои и связи между компонентами.

> Диаграмма классов находится в файле `classes.puml`

**Ключевые элементы:**

- **Слой домена (`src/domain/models`)** — чистые бизнес-объекты без зависимостей:
  - `Passenger` — пассажир с билетом и станцией назначения
  - `Ticket` / `TicketType` — билет; типы: `BY_TRIPS`, `DAILY`, `WEEKLY`, `MONTHLY`
  - `Train` / `TrainState` — поезд; состояния: `IN_DEPO`, `IN_TRANSIT`, `AT_STATION`
  - `Station` — станция, агрегирует платформы, турникеты и кассы
  - `Platform` — платформа с очередью ожидающих пассажиров
  - `Turnstile` / `TurnstileState` — турникет; состояния: `LOCKED`, `UNLOCKED`, `LOCKED_DOWN`
  - `TicketOffice` — касса с балансом и прайс-листом
  - `Route` / `RouteStop` — маршрут как упорядоченная последовательность остановок
  - `Money` — денежный тип на основе `Decimal` для точных расчётов

- **Слой приложения (`src/application`)** — сервисы бизнес-операций:
  - `SalesService` — продажа билетов (проверка средств, выдача сдачи)
  - `TransitService` — проход через турникет (валидация, списание поездки)
  - `BoardingService` — посадка/высадка пассажиров на остановке
  - `ScheduleService` / `ActiveDispatch` — тактовая симуляция движения поездов
  - `AppState` — глобальное состояние приложения (словари сущностей)

- **Слой инфраструктуры (`src/infrastructure`)** — хранение данных:
  - `MetroSerializer` — сериализация/десериализация всех сущностей в словари
  - `StorageService` — запись и чтение JSON-файла состояния

- **Слой представления (`src/presentation`)** — CLI-интерфейс:
  - `MetroCLIApp` — точка входа приложения
  - `menus` — обработчики всех пунктов меню
  - `cli_utils` — вспомогательные функции ввода (`get_int`, `get_string`, `select_item`)

- **Исключения (`src/exceptions`)** — доменные ошибки: `InsufficientFundsError`, `TurnstileLockedDownError`, `TicketExpiredError`, `TicketExhaustedError` и др.

## 🔁 Диаграмма состояний

Система включает несколько независимых конечных автоматов.

> Диаграмма состояний находится в файле `boarding_UML.txt` / `packages.puml`

### Состояния поезда (`TrainState`)

| Состояние | Описание |
|-----------|----------|
| `IN_DEPO` | Начальное состояние; поезд в депо, не обслуживает маршрут |
| `IN_TRANSIT` | Поезд следует между остановками; таймер отсчитывает минуты |
| `AT_STATION` | Поезд стоит на платформе; происходит посадка и высадка пассажиров |

### Состояния турникета (`TurnstileState`)

| Состояние | Описание |
|-----------|----------|
| `LOCKED` | Турникет заблокирован; ожидает действительного билета |
| `UNLOCKED` | Турникет разблокирован; пассажир может пройти |
| `LOCKED_DOWN` | Аварийная блокировка; проход невозможен до снятия режима |
